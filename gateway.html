YOUR APP, YOUR ADDRESS

Give your onchain app
a front door.

Your app is already on BAMFS. This makes a small gateway that opens it like any other website. The gateway fetches the original files from the chain.

Your gateway is ready to set up.

  1. Copy your gateway code. Use the button below.
  2. Create a Cloudflare Worker. In Workers & Pages, choose Create → Start with Hello World. Name it, deploy, then open Edit code.
  3. Paste and deploy. Replace the sample code with your gateway code and click Deploy.
  4. Add your connection. In Settings → Variables and Secrets, add your full RPC URL as a Secret named RPC_URL. The bundled public connection can work for an initial test.
  5. Open your website. Use the workers.dev address, or add your domain under Settings → Domains & Routes.
View the code

Use Cloudflare’s Worker editor for an existing Worker, paste this complete module and deploy. It already contains your app’s publication settings.

Let your agent handle setup
Advanced: deploy from a terminal

Download and unzip the gateway package, then run node deploy.mjs with Node 22+. The launcher signs you into Cloudflare. Its configuration uses Workers Paid.

Your connection stays with you.

This page uses your Find3r connection to check your publication. It never asks for a Cloudflare token or private RPC key. After deploying, add your preferred RPC URL in Cloudflare under Variables and Secrets, with name RPC_URL and type Secret. A public default works to start.

This gateway pays for reading your published files. Calls made by the app itself keep using its own connections; the gateway is not a general RPC relay.

One click to prepare. Your account to publish.

Generating a package doesn’t deploy anything or charge you. The Cloudflare sign-in and deployment steps still happen in your account. This first version prepares everything; it isn’t an automatic deployment button yet.

It supports older BAMFS collections and newer org apps. The gateway serves one app, following updates or keeping a fixed version, verifies its file hashes, and caches recovered bytes. Following updates needs no new Worker deployment when you publish a new version of the same BAMFS token. Moving to a new token or contract needs a new pointer; a new BAMFS contract generation may also need an updated reader. Cloudflare is a convenient entrance; your original publication remains on the chain.
